# 私人角色卡内嵌入口

`entry.js` 由《未读之城》的 `scripts/build_embedded_phone.mjs` 构建。它复用本仓库原有手机 UI、业务层、IndexedDB 和 `stTtsDialogue` 设置，输出可由酒馆助手角色脚本加载的父页面 IIFE；不是另一套演示手机。

构建器只读取明确的源码目录和列明的静态资源，不读取酒馆用户目录、手机存储、凭据或环境变量文件。唯一构建环境开关为 `UNREAD_CITY_PHONE_INCLUDE_SOUNDS=1`。普通安装的 `mobile-entry.js` / `index.js` 不受专用构建适配影响。

专用构建把 UI、CSS 和精确分词表放进角色卡。304 个自带 MP3 约 24 MB，默认不携带，也不列出不可播放的自带音效；用户自己的导入音效仍可使用。在构建 Shell 的同一进程环境设置 `UNREAD_CITY_PHONE_INCLUDE_SOUNDS=1` 可让自动构建持续携带完整音效包；一次性 `--include-sounds` 只影响该次生成，下次默认构建会重新省略。

内嵌生命周期只管理自己创建的实例，保留源插件的能力检查。为避免新卡片加载时沿用旧设置发生自动请求，专用构建关闭启动、聊天事件及楼层重绘驱动的自动配音、配图、消息、来电、记忆总结与自动同步；手机内明确点击的功能继续使用原实现。手机数据仍按来源与角色卡分区，跨设备迁移需使用手机原有备份/同步。

启动时的旧系统消息清理、旧“正文也带上”记忆开关迁移在专用构建中也被停用，避免仅打开卡片就维护或删改已有手机历史。

整体上游尚未声明许可证；该入口用于用户自己的本地私人维护，不代表取得公开再分发授权。Marked 和 Apache-2.0 分词表许可随构建保存。Fish MCP 独立实验控制面板和它的服务端没有打包进来；原手机引擎已有的明确授权和接口仍各自适用。

《未读之城》主动绑定 `STiPhonieStoryHost` 时，NPC 与剧情消息进入当前世界聊天的独立分区，事件去重和已读回执保存在手机自己的聊天存储中；这是对原卡片分区的临时视图覆盖，不改用户设置或迁移原数据。仅携带源码和界面的卡片仍不携带这些私人记录。角色脚本卸载时构建器必须释放 `storyHost`、移除它拥有的 `STiPhonieStoryHost` 全局，再关闭手机后端。
